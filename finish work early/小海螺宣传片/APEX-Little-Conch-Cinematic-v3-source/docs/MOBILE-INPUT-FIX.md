# 手机滑动修复与清晰度验证

## 已证实的问题

旧生产页面 390×844 实测，向上拖动使进度从 0.1800 降至 0.1645（变浅）；新章节 5 秒锁还忽略正向主动手势。原始行为记录见 `qa/growth-v1/mobile-fix/baseline.json`。

## 改动

- `film.js`：向上手势映射正进度，反向手势回看；手势、键盘和继续按钮视为主动输入，可在阅读停留期间响应；滚轮仍保留 5 秒的惯性保护和单次最多推进一项技能的节奏。
- `DiveNavigation.js`：阅读保护区分滚轮与主动输入；业务章节内容、顺序和速度参数不变。
- `PixelDensity.js` / `FirstStageDirector.js`：手机正常渲染像素倍率上限从 1.35 提至 2；超过 200 万像素预算或慢设备降级，避免无限提高分辨率。桌面上限仍为 1.5。
- 更新方向提示，没有修改主叙事文案或素材。

## 验证

新回归测试先失败，修复后全部 21 项测试通过；Vite 构建成功。真实 Chrome 浏览器视口 390×844：向上拖动 62 m → 81 m，0.1800 → 0.2106；320×568：113 m → 122 m；反向拖动 152 m → 146 m。1440×900、390×844、320×568 均无横向溢出，控制台警告/错误 0。截图与读数见 `qa/growth-v1/mobile-fix/local-*`。

限制：浏览器由鼠标拖动测试 Pointer Events，并非物理 iOS/Android 触摸；浏览器实际 devicePixelRatio 为 1，高密度上限通过函数测试验证。素材原分辨率没有提高，不把像素倍率等同新细节；天空和海底仍需要 GPT 的高分辨率正式素材。

## 参考站技术观察

公开 Skydive 模块以 ScrollTrigger 的页面进度更新场景 targetProgress，镜头与画面深度共用平滑进度。参考站手机像素倍率上限实际为 1.25，清晰感同时来自优质素材、空间分层和运动控制；单纯更换部署平台不会提高画质。其域名使用 Vercel，私有部署流程未知。只学习技术原则，没有复制专有素材。
