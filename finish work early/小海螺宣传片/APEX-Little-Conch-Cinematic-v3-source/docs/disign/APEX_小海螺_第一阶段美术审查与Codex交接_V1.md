# APEX STUDIO | THE LITTLE CONCH
## 第一阶段美术导演审查与 Codex 交接 · V1

状态：**概念视觉可作方向参考；本轮无一项资产获准以成品身份替换工程占位。**
参考作品：https://annacheng8.vercel.app/CARD/ （仅研究镜头与空间关系；不复制受保护资产）

### 一、导演决策

- 开场继续采用第一人称写实机舱 POV：中央门洞是唯一的视觉出口。门框、舱壁、踏板、门板、门闩、双手必须是**独立实体或独立透明图层**。
- 工业质感应来自可解释的机械结构和真实使用痕迹：铰链、螺丝、加强筋、密封条、滑轨、连接件、脚踩磨损。禁止平均分布的随机划痕。
- 光照基准：海面外景左上方低角度暖日光；机舱由该外光产生边缘高光，右侧及深处为偏蓝灰的环境漫反射。所有素材共享同一光照方向与摄影曝光。
- 舱门初始关闭时，环境应压迫狭窄；用户自主开门后，天空开放成为强烈的视觉反差。不允许通过一张封闭贴图把舱门、天空、手、贴纸烘焙在一起。
- 人类双手属于**身份转化之前**的 POV 道具：开门、支撑、出舱、迎风、收手；穿水后消失，由小海螺壳口光学边缘接管。后续小海螺 POV 不保留人类手部。

| 维度 | 冻结目标 |

**待 Codex 技术确认的阻塞问题**：原交接写明门洞中心 `(0,248,-1)`、本地坐标 Y=0、全局单位为米。该数值彼此矛盾；如果 `248` 表示厘米，应改为 `2.48m`，如果已经是父节点局部坐标则可能是 `(0,0,-1)`。在绑定任何 GLB 和手部前，请 Codex 明确相机、舱门、铰链、门框的父子坐标系和真实变换矩阵。不要默默猜测。

### 三、第一批优先资产 / 通过标准

#### A1 aircraft-cabin-surround
- 4096×2304，RGBA；必须中央真透明 alpha=0（门洞内任何像素均不容许天空、门、手、棋盘格、水面）。
- 左右门框、上下横梁、底部踏板形成自然的前景框；可以有舱壁电缆与密封条，但不能在框内增加悬浮饰物。
- 关键是零件合理、近大远小、漆层粗糙度丰富，中心透视与 Codex 64° 目标 FOV 一致。
- 交付 `aircraft-cabin-surround.png` + `aircraft-cabin-surround-mobile-guide.png`，后者是构图指南，不替代真正响应式裁切。
- 验证：将 RGBA 图直接叠在蓝、白、黑、透明棋盘四种背景上，检查穿洞、边缘和暖光方向。

#### A2 aircraft-door-basecolor + PBR
- 门板 2048×3072 独立纹理；五金和舱门铰链优先几何独立，以实现可信的旋转与遮挡。
- 至少包括 `baseColor`、`normal`、`roughness`、`metalness` 四张与同一 UV 一一对应的合法纹理；不能将概念图里的一列假材质示意图当作 PBR maps。
- 门板 baseColor 不烘焙强烈环境阴影；金属表面随机划痕需要方向性和密度控制。张贴标语须独立于门板，以免以后调整位置。
- 首批允许先制作合格门板与独立五金，不必在这一轮凑齐低品质 PBR。

#### A3 hand-brace-left / hand-brace-right
- 两张独立 1536×2048 RGBA；眼睛到手的透视必须正确，两手的手套、袖口、缝线、污渍程度是同一套服装。
- 左手从下左入画扶住左门框，右手从下右伸向把手；关节数、拇指朝向、抓握接触和腕部角度必须符合物理姿态。
- 不出现脚、躯干、其他人物。不要白边、落地投影或无法区分的假透明背景。
- 扶门图要与机舱基线截图进行透视叠合验收；如使用 3D 手臂模型，则要求模型与相机绑定并校核遮挡。

#### B 阶段（A 通过后）
- `hand-freefall-left/right`：同一对手、同一衣服；在左右下角 15–22% 范围内，不遮中心 HUD。
- `conch-aperture-rim`：4096×2304 RGBA + 1440×3120 手机版，中心 >=85% 通透，不出现完整海螺主体、卡通触角、人类手或霓虹框。
- 云层、水花图集、水下 panorama 等增强项在 A1–A3 静态镜头通过后再制作；海底现有章节暂不更改。

### 四、资产审查分级

- **G0 方向概念**：仅用于美术基准，不接入游戏。当前两张资产综合概念板属于 G0。
- **G1 静帧构图通过**：素材已独立、构图和光线匹配、可叠加机舱截图。
- **G2 技术可接入**：满足输出尺寸、真实 alpha、无白边、文件命名正确、可在 `assetManifest.js` 引用。
- **G3 镜头测试通过**：在开门/前倾/起跳动画中没有透视错位、穿帮或遮挡，移动端可用。
- **G4 正式美术验收**：所有关键帧、动作衔接和画面一致性通过导演复核。

只允许 G2 以上替换工程占位，并在 Git 提交说明素材来源/授权。禁止将 G0 的低分辨率综合拼图硬裁切、放大，冒充正式透明素材。

### 五、Codex 接入和反馈规范

1. 在保留工程版本的独立分支上接入；原始 v3 和现有 shader 占位均需可回滚。
2. 新素材先在机舱静帧（door closed）叠加，不要一上来就联调全部动画。
3. 提交以下真实浏览器截图：1440×900、390×844、320×568 以及横屏。另提供开门 25% / 50% / 100% 的截图。
4. QA 路由依项目已有 `http://127.0.0.1:4180/?qa=1` 使用；报告真实结果，不编造通过结论。
5. 确认 `assetManifest.js` 预留字段的真实路径、命名和浏览器 URL；若为左右两层手部，在 `HumanForeground.js` 拆分并独立绑定。
6. 记录每个资源：原始尺寸、实际 alpha、版权来源、压缩后大小、平均帧率影响以及降级路径。
7. 如透明图适配 64° VFOV 失败，先报告偏差并给出对齐图，不要悄悄用 CSS 任意拉伸。
