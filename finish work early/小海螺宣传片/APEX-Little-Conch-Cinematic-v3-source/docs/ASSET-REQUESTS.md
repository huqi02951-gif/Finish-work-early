# 第一阶段 · 给 GPT 创意导演的素材交接

状态：镜头工程联调版。未通过最终美术验收。目标仍是第一人称机舱 → 手动开门 → 连续坠落 → 入水 → 小海螺感知视角。本轮不改变深海章节。

## 已检出的原素材问题

- `cabin.webp`（1600×900）与 `hatch.webp`（980×1280）为平面插画风，刮痕重复、五金与表面缺少实物质感。现阶段只沿用作工程底图。
- `pov-hands.webp` 仅 388×350，内容混有脚/身体及不完整裁切，不适合作为扶门或双臂特写。保留原文件，但关闭默认显示。
- `seabed.webp` 可以继续作为远景背景，已放入包围视野的曲面；不是三维珊瑚资产。
- 云、波面、折射、泡沫、气泡为工程着色器效果，未采用任何原参考站图片、模型或字体。

## 接入与验收

`src/first-stage/assetManifest.js` 是资源入口。四个独立手部字段 `handBraceLeft`、`handBraceRight`、`handFreefallLeft`、`handFreefallRight` 默认 null；目标文件在 `assets/approved/`，分别为 `hand-brace-left.png`、`hand-brace-right.png`、`hand-freefall-left.png`、`hand-freefall-right.png`。接入时使用 `new URL('../../assets/approved/文件名.png', import.meta.url).href`。开发 URL 为 `/assets/approved/文件名.png`，构建后由 Vite 生成带哈希 URL。未交付的文件不会被请求。

`HumanForeground.js` 已拆分左右层。扶框左手继承机舱左侧接触点，右手继承旋转门闩；两者开启深度测试。坠落手独立绑定相机，保持源图比例，限于左右下方，入水前收回。每张扶门图需附握持点 UV（左下原点），当前 UV 只是接口初值，必须用正式图校准，不能称为已通过抓握验收。透明平面不能完成真实骨骼弯曲；若需右臂完整连续抓握旋转，优先提供同一服装的绑定 GLB 手臂。

PBR 的 `doorNormal`、`doorRoughness`、`doorMetalness` 槽已预留并按线性数据加载；`hatch` 为 sRGB 色图。`shellRim` 仍是预留槽，收到成品后另行接入，不把现有着色器细弧冒充定装设计。A1 新门框图需要在现有几何门框上对齐，不能仅换路径便宣称验收。

使用 `http://127.0.0.1:4180/?qa=1` 的机舱/开门 25%/50%/100%/跃出/自由落体/近海/穿水/水下/抵达按钮对齐。检查 1440×900、390×844、320×568 和横屏。每张图保留同构图、光向与尺度；首轮先批准静态机舱与手，再制作动作变体。

参考只用于镜头与空间关系：[Anna Cheng Freefall](https://annacheng8.vercel.app/CARD/)。未经许可不得抽取或复用其专有资产。
